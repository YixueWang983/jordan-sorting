## 2. 最低交付及效率验收

后端必须支持真实 Jordan Sorting 调用，不只是独立树类。操作级对照、外部输出判据和必要结构检查通过后才进入比较。主线同时保留当前普通列表作为对照；共享核心调整后双方重新验证、匹配计时。

必须维护 [接入与成本表](../development/backend_integration_cost_map_20261011.md)：每项含调用位置、前提、接口、真实工作、目标成本、依据与缺口。规格的摊还界只是目标，不能直接移植给代码。make-list、边界插入、split、owner 查询、元数据维护、初始化、输出和局部检查全部计入成本解释。

不要求跑赢 Python `sorted` 才算实现成立，也不以“比普通列表快”证明操作界。理论来源核对、代码语义正确性、实现操作界、完整排序界、实测表现分别陈述；尚未闭合的证明列出具体依赖。高效后端要求不能通过将未完成实现改称设计贡献来满足。

## 4. 后端与共享核心必须同时推进

实现顺序：确认操作/访问契约 → 真实端点表示 → 边界插入 → split/重平衡 → header/owner slots → 完整排序 → 扩大验证。

接入范围不仅是 `parent_pair_id`、`sibling_list_id`、`pair_ids`。`Step3AResult`/`Step3BResult`、`stage_results`、trace、metrics 推导、完整状态验证与 replay 都依赖旧表示。

特别注意：`stage_results` 还承担阶段顺序检查；`_record_stage_result` 并不只在 trace 模式运行。不能把它整体视为可关掉的诊断。保留正常执行所需的常数大小阶段状态；完整审计视图和诊断快照可独立版本化。跨后端比较逻辑语义，不强制物理 list ID 一样；同后端 replay 仍是 same-core 一致性检查。

enclosing 分支可能只需要 pair 自身的 child slots，不可对所有 finite pair 统一要求端点 owner 查询。每一次 `boundary_list` 调用须写出 locality 前提；任意内部 pair 查询或祖先遍历必须公开，不可悄悄放回 minimal 热路径。

操作模型仅建立语义测试底座。还必须补上真实红黑/rib 重平衡、几何区间/端点、family 与无环约束、Jordan 两个 z1 修正、失败状态传播、各执行模式、阶段记录与审计适配。详见接入表中的缺口。

## 5. 分层输入与最终双方资格

核心目标约 140 个唯一 rank 输入：长度 32/33、64/65、128/129、256/257、512/513；每长度至多 2 个 strict-flat，low/medium/heavy 各 4 个，即目标 `10 × (2+4+4+4)`。

扩展目标约 380：同十个长度，low/medium/heavy 各扩至 12 个。两者都是覆盖配额，不是统计充分性或保证达到的样本数。镜像保留 base identity，数值重标记和计时重复不能充作独立输入。

正式计时前冻结生成规则、种子、候选预算、保留顺序、rank 去重、结构分类、资源预算和缺额处理。先探查大规模复杂结构的资格阻塞，不先填满简单格子。140 可因事先声明的资源限制调整，不能看到速度以后筛选。

**最终双方资格是新的必经门槛：**对最终实际测量的源码/共享核心、backend、policy 和逐个输入身份，分别完成认证、checked 与独立新状态的 minimal 输出比较；保存双方状态。今天普通列表的 16 例、历史 85 例或更早验证都不能自动沿用。共享核心或审计适配变更后需评估影响并重验双方。

至少记录 `input_hash / rank_hash / source_id / base_id / structure / n / backend / source_identity / policy / command / status / elapsed / timeout_budget / log_hash`。不适用字段明确解释，不能用空值掩盖未执行。

合法输入上的错误属于阻塞缺陷，不能删掉该例恢复“通过”。TIMEOUT/RESOURCE_FAILURE/NOT_RUN 不算 PASS；资格导致的样本偏差如实披露。双方共同合格集及各自失败记录都保留；不得只报交集隐藏一方的错误。

## 6. 计时与论文证据

先用少量预选输入跑通生成→资格→计时→数据验证→图表流程，再冻结正式协议。5 次 warm-up、20 次测量仅作 pilot 的起始候选；是否批量调用由计时粒度和预算检查后决定。无论是否批处理，每次调用新建状态。

同输入、同环境、同计时口径重测双方，包含初始化、完整 Step、输出恢复；oracle、expected 比较、完整 checked 和操作计数在计时外。必要的运行期局部检查仍须保留且计入成本，不因后端名字或都叫 minimal 而视为负担相同。

保留每输入分布、median/IQR 和配对时间比；重复数不当作输入样本数。validator 必须拒绝缺行、重复身份、错误输出、无效计时、哈希或汇总不一致。失败归档不删除。

旧 60/3,600 结果保持历史身份，图注也标版本；本轮不另做“去回滚收益”因果实验。有限曲线不能证明线性。论文章节随阶段更新；任何未完成的操作或证明仍标计划/缺口。

## 7. 阻塞处理：调整安排，不能取消最低交付

| 门槛失败 | 动作 |
| --- | --- |
| 10-12 关键表示或 locality 仍未解决 | 暂停输入扩展，先关闭接口/成本阻塞 |

| 10-18 验证或关键效率要求未满足 | 不进入正式比较；重新协调时间/交付安排，不把后端改为可选 |

先压缩 380 满配、额外规模、多机器、普通列表优化、通用框架、因果对照和展示材料。不压缩必要正确性、成本解释、证据真实性；不默认消耗 23—24 日检查缓冲。

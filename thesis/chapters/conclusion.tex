\chapter{Conclusion}
\label{chap:conclusion}

\section{Summary}
\label{sec:conclusion-summary}

This thesis translated the control flow of the 1990 Simplified Jordan Sorting
algorithm into an executable and auditable Python implementation. The
reconstruction maintains a partial sorted order, upper and lower pair
families, and sibling-list ownership while executing the paper-facing
Step~1/2/3 procedure. It makes explicit the orientation, endpoint, and
first-point cases needed by the implementation and records where those choices
are reconstruction decisions rather than uniquely determined statements of
the paper.

The concrete backend uses ordinary Python lists. It therefore separates the
incremental algorithmic structure from the specialized data structures on
which the historical linear-time results depend. The project further separates
the independently recovering paper core from an oracle-backed reference
pipeline: the paper core obtains its output from its maintained partial order,
whereas the reference path deliberately returns oracle-derived sorted output.
Fixed execution policies, checked diagnostics, deterministic replay, and
transactional sibling-list updates make this boundary observable and testable.

The empirical study evaluated oracle-certified valid-input sorting under a
frozen protocol. It compared Python sort, the complete oracle-backed reference
pipeline, and the pre-certified paper core in \texttt{minimal} mode. Immutable
run evidence and an independent validator preserved the cases, schedules,
correctness fields, summaries, and audit records used for the analysis.

\section{Answers to the Research Questions}
\label{sec:conclusion-questions}

\subsection{RQ1: Executable Reconstruction and Correctness}
\label{sec:conclusion-rq1}

The available evidence supports an affirmative answer within the evaluated
scope. For pre-certified valid inputs, the ordinary-list reconstruction
executes the shared paper-facing control flow and independently recovers sorted
order from maintained state. Focused tests, bounded exhaustive repository
validation, checked state audits, and deterministic replay exercise the
partial-order and sibling-family invariants. In the frozen Week~12 experiment,
all 3600 measured rows belong to 60 exact cases that each passed one untimed
checked audit before timing. Every row has correct output and no recorded
error; all 180 case-algorithm summaries are correct and error-free, and all 60
case audits pass. These records are summarized in
\cref{sec:results-correctness}.

This answer is empirical and bounded. It does not constitute a mathematical
proof for every Jordan sequence, nor does it establish recognition of
arbitrary inputs. Oracle certification supplies the valid-input precondition,
but not the paper core's sorted output.

\subsection{RQ2: Observed Runtime Behavior}
\label{sec:conclusion-rq2}

Across the five tested sizes, the median exact-case paper/reference ratio
decreases from $3.226$ at $n=32$ to $0.567$ at $n=512$. It is above one through
$n=128$ and below one at $n=256$ and $n=512$. The same size ordering and
adjacent-size direction occur in the Week~11 pilot and the larger Week~12
formal run when each run is compared through its own within-case ratios.
Python sort has the lowest median call time at every tested size.

These observations answer the question only under the frozen timing scopes.
The reference measurement includes its complete oracle-backed pipeline; the
paper measurement includes only the pre-certified \texttt{minimal} call, with
oracle certification and checked diagnostics outside timing. The ratio is
therefore not a like-for-like end-to-end speedup. Five tested sizes and an
ordinary-list backend also do not establish an asymptotic complexity result.
Week~11 and Week~12 absolute runtimes are not pooled.
The matched-case ratios and directional comparison are reported in
\cref{sec:results-ratios,sec:results-replication}.

\subsection{RQ3: Structure and Implementation Cost}
\label{sec:conclusion-rq3}

The exploratory analysis finds positive within-size associations between
reference runtime and both maximum depth and containment-pair density at every
tested size. The corresponding paper-runtime coefficients are smaller and
more variable in sign or magnitude. Checked sibling scans, splits, copied
items, and transferred items each have positive descriptive associations with
minimal paper runtime across the tested sizes. The invariant-check counter is
constant within each size, so its within-size Spearman coefficient is
undefined rather than zero.

These findings describe the controlled sample; they do not identify causal
costs. Structural families are intentionally unbalanced, and checked counters
are collected by an untimed policy while runtime comes from the
\texttt{minimal} policy. The results therefore motivate more targeted
experiments but do not show that one structural feature causes a particular
runtime change or that the tested generators represent all valid Jordan
sequences. The underlying coefficients are reported in
\cref{sec:results-exploratory}.

\section{Contributions in Context}
\label{sec:conclusion-contributions}

The central contribution is a separation of concerns that the theoretical
description can obscure when read as an implementation recipe. The project
distinguishes:
\begin{enumerate}
  \item geometric validity and external certification;
  \item the incremental sorting control flow and its independent output state;
  \item the concrete sibling-list representation and its operation costs; and
  \item correctness diagnostics and evidence validation outside the minimal
    timed path.
\end{enumerate}

This separation supports an executable reconstruction without silently
claiming the theoretical backend. It also permits reproducible empirical
statements whose provenance and timing boundaries can be checked after the
run. The contribution is consequently one of reconstruction, correctness
engineering, and bounded empirical characterization. It is not an
implementation or experimental demonstration of linear-time Jordan sorting.

\section{Future Work}
\label{sec:conclusion-future-work}

Several extensions follow directly from the limitations of the present work.

First, the ordinary sibling-list backend could be replaced by a data structure
that realizes the historical locality bounds, such as a carefully specified
heterogeneous finger-tree implementation. Keeping the existing paper-facing
control flow and audit contracts would make it possible to isolate the effect
of the backend while preserving output provenance. Such an extension would
require its own correctness argument and complexity analysis; faster measured
calls alone would not establish the theoretical bound.

Second, the executable anchor and orientation clarifications could be given a
formal proof against an explicit Jordan-sequence model. The present repository
validation supplies strong bounded evidence and counterexample-driven
regression tests, but a proof would address all valid inputs rather than only
enumerated and generated cases.

Third, recognition should be studied through a separate protocol that includes
invalid inputs and reason-level correctness. The valid-input sorting evidence
reported here cannot answer recognition questions. Error-correcting Jordan
sorting and geometric applications such as polygon clipping likewise remain
separate extensions.

Finally, future experiments could use larger size ranges, more balanced and
more varied case families, equivalent end-to-end pipeline scopes, and multiple
recorded runtime environments. These changes would improve empirical reach,
but they should retain matched-case ratios, immutable evidence, independent
validation, and explicit separation between descriptive trends and asymptotic
claims. Absolute runtimes from distinct environments should remain separate.

\section{Closing Perspective}
\label{sec:conclusion-closing}

Jordan sorting illustrates why implementing a theoretically efficient
algorithm is not merely a matter of transcribing pseudocode. The structural
idea, the dynamic representation that realizes its bound, and the evidence
needed to evaluate a concrete program are distinct objects. By reconstructing
the incremental algorithm with ordinary lists and making those distinctions
explicit, this thesis provides a testable bridge between the historical
description and an executable research implementation. Its conclusions are
deliberately bounded, but within those bounds the reconstruction recovers its
own sorted output, survives independent state and evidence validation, and
exhibits a reproducible runtime pattern across the tested cases.

## 已实际核对

1. **列表身份与物理对象不是同一生命周期。**
   `heterogeneous_finger_backend.py:split_value` 无论返回一侧还是两侧，都先退役
   old header，再以 `_next_list_id` 为每个非空结果创建新 header。递增计数器不回退。
   `make_list` 使用同一分配器；端插返回原 header.list_id。树层 `split` 的单侧
   快速返回旧物理组件，不等于公开操作保留旧 list ID。稳定 pair/leaf/handle
   与 fresh header 并不冲突。本次 `seen_ids` 检查契约要求新身份，而不要求编号连续。

2. **join 黑高基准与累计费用。**
   核对 `join_down` 的两侧根黑化、等 rank 黑根基例、较高侧单路递归、回溯修复与
   最终根黑化；既有证明使用 `nu=r+[red root]`，没有把黑化前的 rank 当作基准。
   `split_down` 的回溯只将一个未动 sibling 加入一侧累计输出，其他侧保留；这与
   分别对两个累计 rank 序列收费的组织一致。`a-b<=1`、结果 rank 不下降以及局部
   balance 契约仍是望远镜界的必要引理，不能用本轮校准或测试次数替代证明。

3. **另一 rib 的访问位置与角色变化。**
   `sibling_children` 仅在 sibling 不是 INTERIOR 时调用 `rib_child`。
   `repair_short` 的非根 sibling 为向下组件；到根才涉及另一 rib。红 sibling
   旋转后旧 parent 变成非根；near 旋转后最多再取一次 sibling children，随后 far
   旋转返回；黑兄弟传播到根结束。因此既有“至多两次、根附近行走”的控制流说明
   与代码相符，但路径长度仍要按初始 rank 与传播次数支付，不能记成常数。

4. **原文 locality 的适用范围。**
   实际渲染并阅读仓库 `docs/papers/simplified_linear_jordan_sorting.pdf` 印刷页
   88、89（图3、4、5和相邻正文）。原引理确实要求最新 pair 是该 family 的 child，
   并针对离开末点后的首次重入；dummy 情形有跨越全部有限端点的外端例外。
   同页分组规则另列“最新 pair 为 parent 时单列表”；第89页将 locality 用于
   Step 3(a) 的末端、3(b) 的首端访问。项目第8.3节的有限 parent 补充论证不能
   直接冒充这条 child 前提的原文引理。第9节两个 z1 修正与几何端点的解释也仍
   要作为项目的可执行澄清审阅。

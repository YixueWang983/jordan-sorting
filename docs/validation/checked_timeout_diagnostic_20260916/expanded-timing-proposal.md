# 扩展计时实验草案（尚未执行）

本草案基于 071973c 的实现与归档。原正式实验仍为 60 cases / 3,600 measured rows；扩展非计时验证仍按原归档报告 209 PASS、1 TIMEOUT、4 NOT_RUN。独立诊断不得回写历史状态，也不得充当新增性能样本。

## 先解决资源资格，再固定计时样本

归档中的 checked 是 paper_jordan_diagnostics_valid：每个前缀均做完整状态校验和 same-core replay。它与 paper_jordan_sort_valid(..., execution_mode='checked') 不是相同的诊断范围，更不能用它的耗时代表 minimal 排序调用。审计预算与测量预算必须分开记录。不能通过关闭 replay 或降低校验强度，然后把结果标成原来的完整审计。

候选主规模为 32/33、64/65、128/129、256/257、512/513。它们是待资格验证的规模，不保证每种结构在当前预算内完成。1024/1025 暂列探索层，不进入正式主表；本次没有执行这两个规模。先冻结少量、按结构挑选的资源预检输入，完整审计每例上限建议 180 秒、整批预检上限 30 分钟。上限是拟议运行预算，并非已证实的可执行范围。发生输出或状态错误则停下诊断；超时只表示未完成，不记作算法错误或通过。正式候选中出现审计超时，应公布该格未完成并调整下一份预注册计划，不以更容易的输入悄悄替换。

## 按实际结构分层

按 structure_profile 的现有分类划分 strict_flat、low_nesting_valid、medium_nesting_valid、nested_heavy_valid，而非以生成器名称替代实际分类。沿用分类阈值：nesting_count=0 为 flat；depth<=1 且 nesting_density<=0.35 为 low；其余 depth<=3 且 density<=0.70 为 medium；其余为 heavy。

建议每个规模、每个结构格以最多 4 个不同基础输入为目标，共最多 160 个基础输入。该数是设计上限，不是已有用例数量。生成阶段固定种子、尝试上限及选择规则，去重并保存所有拒绝原因。严格 flat 或其他格若只有少量不同构造，应公开实际数目，不能靠重复输入补齐。优先在 low / medium 格补足当前缺口，heavy 格内再记录深度、root count、containment count，避免把所有 heavy 都当作一种形状。

每个基础输入可配一个反射输入作为配对结构检查；保留 base_case_id，不能把反射当成独立随机样本。先在基础输入与反射内部汇总，再在结构格内汇总，以免双重加权。生成失败、结构格缺额和重复都在 manifest 中保留。固定用例表后才开始审计和计时，不根据速度挑选或剔除输入。

## 测量协议

使用新的独立配置与运行目录，不改写旧 Week 12 runner 的冻结 gate，也不把新行混入旧归档。固定源码哈希、环境、输入哈希和随机顺序种子。沿用 3 个调用范围：Python sorted；reference 的完整公开调用（含其 oracle 与辅助结构工作）；paper minimal valid-input 调用（初始化、Step 1/2/3 与 output recovery 均在计时内）。外部认证、expected-output 比较、结构分类、完整 checked audit 都在计时外；paper core 不接收 oracle 答案。

每个正式 case 完整 audit 一次，测量前 5 次 warm-up、20 次 measured calls；轮换三个算法的顺序，统一 GC、输入拷贝与计时边界。输出恢复仍留在 paper 时间内。基础/反射资源预检与正式 audit 分别记录，不能将跨阶段总调用次数说成一次。预检完成后应重新固定环境并留出冷却时间，避免诊断与测量并行。先用独立 pilot 检查计时分辨率与资源预算，pilot 不并入正式统计；若必须更改批量计时方式，应预先修订协议，并与历史单调用结果明确区分。

逐 case 先取 20 次调用时间的中位数；paper/reference ratio = median(paper times) / median(reference times)。先按结构格、规模分别报告这些 case ratios 的中位数。主要展示每个 scope 的绝对时间与分布；跨格总体统计仅在公开加权规则和缺额情况后提供。不同 scope 的比值不能归因于某个单独函数或单项结构成本，不能从墙钟斜率证明理论复杂度。

最终报告每格计划、有效、重复、失败、超时、未执行数及基础/反射数量。测量记录数按实际合格 case 数 × 3 × 20 计算，不能预先宣称已得到 9,600 或 19,200 行。结构覆盖、正确性检查与性能证据分开报告。Finger-tree 仍是未来工作。

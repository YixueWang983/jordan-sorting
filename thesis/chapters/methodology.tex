\section{Study Scope and Version Boundary}
\label{sec:method-positioning}
\label{sec:method-experiment-stages}
\label{sec:method-scope}

Experimental algorithmics studies concrete programs, inputs and machines
\parencite{mcgeoch2012guide}; algorithm engineering separates implementation,
analysis and evaluation \parencite{sanders2009engineering}. Accordingly, the
current matched protocol and the historical measurements are distinct studies.
The current ordinary-list and tree implementations have completed qualification,
separate batch calibration and formal paired measurement. Current results in
\cref{chap:results} use source \texttt{4a83fa6}; the older rollback-enabled
ordinary-list study remains a separate historical section. Neither calibration
nor a later checker changes an old execution's source identity.

\section{Current Inputs and Qualification}

The frozen common set contains 140 unique rank inputs at ten lengths:
$32,33$, $64,65$, $128,129$, $256,257$ and $512,513$, with two strict-flat and four each of
low, medium and heavy nesting per length. Fixed constructors, seeds, candidate
budgets, rank deduplication and first-eligible retention preceded timing.
These are structural constructions, not random independent observations.
All 140 cases pass both backends' v2 checks. Their 3,788 recorded splits per
backend all have an empty output side: they exercise ownership transfer but
not the tree's interior two-sided split path.

A separate targeted set uses the existing construction at $n=128,129$,
$k=3,7,19$, with each direction and its mirror: twelve cases, all qualified.
Actual traces contain twelve two-sided splits per backend, with smaller sides
3, 7 and 19 occurring four times each. Each source has size 61 and a finite
owner; later direct updates affect only the retained side. This bounded
coverage does not represent all scales, ratios or follow-up operations.
The two sets remain separate, not 152 independent random samples.

For each input/backend, v2 advances two independent checked instances,
compares every completed prefix, and executes a third fresh checked replay
at the end. Another fresh minimal call uses the intended timing configuration.
Each output is compared to external sorting, without feeding that expectation
into the core. These checks establish finite execution evidence, not a general
proof. The old fresh-replay-at-every-prefix protocol remains a bounded
reference and is not described as identical coverage.

\subsection{Historical Input Protocol}
\label{sec:method-protocol}
\label{sec:method-case-audit}

The archived formal study instead used 60 cases: at each
$n\in\{32,64,128,256,512\}$, one flat, one nested and ten seeded incremental
cases. Generation seed \texttt{20261201} and case identities determine the
inputs. Duplicate hashes were rejected within family--size groups, not by a
global rank rule. All 60 passed oracle validity, distinctness, structural
profiling and checked ordinary-list diagnostics before warm-up. Failures
stopped the run; checked outputs were compared externally. The ten-to-one
family imbalance remains visible in historical aggregate results.

\section{Compared Implementations and Call Scopes}
\label{sec:method-implementations}

The current comparison uses the same public Jordan core with ordinary-list or
heterogeneous-finger storage, both minimal; the tree explicitly sets
\texttt{detailed\_work=False}. Every call initializes fresh state and recovers
its output. Production source hashes match the qualified versions. Source or
configuration changes require checking which qualification and measurements
must be renewed. A tool-only archive check is recorded separately.

\section{Timing, Calibration and Scheduling}
\label{sec:method-timing}

Current timing uses \nolinkurl{time.perf_counter_ns()}. The interval includes
fresh initialization, the main loop, output recovery, the batch loop and output
append. External comparisons, pre-batch garbage collection, compression and
persistence are outside it. GC remains enabled, with thresholds recorded;
necessary local checks are not removed. A batch is the statistical unit:
dividing its duration by B does not create B independent observations.

Calibration tries $B=1,2,4,8,16,32,64,128$ in order, three batches per backend
at each attempted value. It chooses the first common B for which both median
batch durations reach 10 ms, irrespective of their ratio. All attempts and
outputs are retained. At source \texttt{c5b5ac3}, the common set selected
B=1,2,4,8,16,32 for respectively 24,20,20,28,21,27 inputs; all twelve targeted
inputs selected B=8. Independent reconstruction accepted both campaigns,
within their separate 600-second budgets. These are granularity decisions,
not formal speed comparisons or statistical-precision guarantees.

\subsection{Scheduling and Noise}
\label{sec:method-scheduling}

Calibration alternates the first backend by case index, candidate index and
repeat. The executed formal protocol shuffles cases with seed
\texttt{20261015}, uses five warm-up calls per backend and twenty paired batches
at each frozen B, alternating first position by case index and round. Each
backend is first ten times. Failures stop subsequent cases; timeouts preserve
committed batches and leave explicit unrun statuses. No outlier removal or
speed-based input replacement is allowed.

Historically, each of three algorithms instead received five warm-ups and
twenty individually timed calls per input. Case/order seeds were
\texttt{20261203}/\texttt{20261202}, with cyclic position rotation. The old
wrapper disabled GC only around the measured call and restored its prior state;
that policy is not inherited by the current comparison. Controlled scheduling
reduces fixed-position bias, not all thermal or operating-system noise
\parencite{mytkowicz2009wrong}. Repetition alone does not establish adequate
statistical power \parencite{kalibera2013benchmarking}.

\subsection{Recorded Environment}
\label{sec:method-environment}

Each current archive binds source hashes, Python executable/version/flags,
platform, CPU, RAM, power observations, GC thresholds and monotonic-clock
metadata. Calibration and formal execution must match source and recorded
machine/runtime settings. Tests, qualification and compilation were not run
concurrently with calibration or formal sampling. The current formal archives
record Apple M4/arm64, 16 GB RAM, ten logical CPUs, macOS 26.6 and CPython
3.12.14; their captured power state is battery at 100\%. The historical formal archive records Apple
M4/arm64, 16 GB RAM, ten logical CPUs, macOS 26.6 and CPython 3.12.4, with its
own preflight; these are not claims about today's runtime.

\section{Aggregation and Statistical Units}
\label{sec:method-aggregation}

The current formal protocol reports twenty batch-derived
per-call durations per input/backend, their median and R7-interpolated quartiles
and IQR, and the paired ratio of backend medians. Related constructions and
mirrors remain dependent; cross-input summaries are descriptive.

The historical archive contains $60\times3\times20=3600$ measured calls and
180 case--algorithm summaries. Its quartiles use median-of-halves, not R7.
The 45 family--size--algorithm groups aggregate case medians; ratios are formed
within inputs before equal-case aggregation. Counter associations are
exploratory, not causal decompositions of runtime.

\section{Evidence Binding and Acceptance}
\label{sec:method-evidence}

The historical formal/pilot sources are \texttt{98868b1}/\texttt{01f6480}.
The current 140-case and twelve-case qualification producers are
\texttt{3cafb44} and \texttt{668371f}; checker/calibration source is
\texttt{c5b5ac3}. Formal executions use \texttt{4a83fa6}, with identical Python
source hashes, frozen B tables and matching required environment fields. Full
hashes and immutable archive locations are indexed in
\cref{sec:appendix-revision-bindings}. New checking does not relabel old runs.

Each current record is independently compressed, synchronized and atomically
committed. A terminated worker cannot erase earlier completed records. A new
archive stores its configuration before execution and binds records, decisions
and environment by manifest. Resource wall time includes checking and storage
and is separate from a measured call. Old archives are never resealed to imply
new execution.

\subsection{Fail-Closed Validation}
\label{sec:method-validation}

The current archive checker verifies schemas, source blobs, input identities,
outputs, event order, sizes, owners, counters and list-ID lifetimes. A live-ID
map checks current membership; a separate seen-ID set prevents a singleton or
split output from reusing any retired ID. Boundary insertion keeps its live
ID. Read-only rechecks accept both existing datasets without rerunning sorting.
The measurement validator independently reconstructs candidate order, every
attempt, the first qualifying common B and output correctness. For formal
archives it reconstructs warm-ups, paired sample order, twenty-batch medians,
R7 quartiles and within-input ratios. A process exit
code alone is insufficient. Historical validation additionally reran the old
checked diagnostics; that behavior is not attributed to the new read-only check.

\section{Interpretation Boundary}
\label{sec:method-boundaries}

Qualification, calibration, proof review and formal measurement are separate
gates. The recorded formal runs followed the source-level manual review and
passed their own binding and reconstruction checks. No calibration ratio enters
the formal results tables, no
historical pilot is renamed as current evidence, and no speed outcome proves
the target asymptotic bound.

\addchap{Abstract}
\label{chap:abstract}

Jordan sorting asks for the order of the intersection points of a simple
curve and a line along the line, given their order along the curve.
Hoffmann et al.\ (1986) and Fung et al.\ (1990) showed that this can be done
in linear time when the underlying dynamic lists support the required
finger-search operations and cost bounds. This thesis presents an executable
Python reconstruction of the 1990 simplified algorithm. A single sorting
procedure runs on two interchangeable backends: ordinary Python lists and a
heterogeneous red--black finger tree. For the tree backend, a manual amortized
analysis gives linear total work on valid inputs under unit-cost comparison
and machine-word assumptions, with expected dictionary lookup and amortized
growth.

In a paired experiment on 140 controlled inputs of length 32--513 and twelve
additional inputs exercising two-sided splits, both backends produced correct
output in all 66,560 measured calls. Nevertheless, the tree backend had a
higher median runtime on every input. The median tree/list ratio was about
2.9 on the common set (range 1.1--3.5) and 3.2 on the split set.
A supplementary diagnostic examined instrumentation hooks, the code that
intercepts field accesses for work counting. Although counting was disabled
in the measured configuration, removing these hooks reduced median tree
runtimes by about 38--52\% and made the tree faster on four of fifteen inputs.
For the measured Python configuration, the tree's stronger structural bound
thus coexists with higher runtime over the tested inputs.

# Jordan sorting 与通用排序的补充比较协议

2026 年 11 月 20 日，作者已确认。根据导师在 11 月 19 日会议上的建议，本实验考察同一批实际规模（n ≤ 513）的有效 Jordan 输入上，两个 Python 后端与 Python 归并排序、快速排序的运行时间和键比较次数。CPython 内置排序另作实用参考线。五种方法在本轮重新测量；主实验的原始记录、结果、报告和论文均保持原样。

## 3. 运行时间

- **计时范围。** 使用原整数输入和 `time.perf_counter_ns()`。输入读取、外部参数准备、树方法生成、显式 `gc.collect()`、正确性检查和落盘均在计时外。批内连续调用同一排序 B 次，保留每次输出，在停止时钟后逐个校验。区间包含排序调用自身的复制、状态初始化和输出恢复，以及同样的批循环和保存返回值开销。保持自动 GC 开启，记录阈值。计数包装器不进入计时路径。
- **独立校准。** 每个输入的每种方法按 2 的幂依序尝试 B = 1、2、4、…、2^20（最大 1,048,576）。每个候选测三批，选中位批时长首次达到 10,000,000 ns 的 B。记录各候选的三个原始批时长与输出校验结果，正式采样固定使用选中的 B。若 2^20 仍未达标，记录该组合没有合格 B 并停止准备。此次上限调整发生在本补充实验的任何测量之前：短输入上的通用排序单次调用远低于原上限所对应的 78.1 µs，尤其是内置排序。两个 Jordan 后端在[主实验校准](../validation/unified_preflight_20261101/batch_sizes.json)中均在 B ≤ 128 时达标；延长候选序列保留全部原候选和首达标规则，因此不影响在原范围内已达标的选取。
- **批内内存。** 每批保留 B 个结果列表，各含 n 个指向已有整数的引用，校验完即释放，然后再测下一批。按本机 64 位 CPython，每个引用 8 字节，每个列表约 56 字节；外层引用约 8B 字节（B 为批大小）。即使同时取 n = 513、B = 2^20，结果本身约 4.1 GiB，考虑列表预留容量约 4.6 GiB，另有解释器及排序临时工作内存。该保留规模对本机 16 GiB 内存可接受；实际批大小取首次达标值，三次重复及五种方法的输出不会同时驻留。
- **正式顺序。** 从清单条目原序出发，以 `random.Random(20261120).shuffle` 一次性打乱全部 302 个输入，保存实际排列。一个连续会话完成五种方法。对打乱后索引为 i 的输入，先进行五轮预热，每轮每种方法调用一次（B = 1）。再进行二十轮正式采样，每轮每种方法各一批。每个阶段的轮号 r 从零开始，第 r 轮将第 1 节的五方法序列向左轮换 (i + r) mod 5 位。每个输入的正式采样中，每种方法在每个位置恰好出现四次。完整会话有 7,550 次预热调用和 30,200 个正式批次。预热和校准记录单列。
- **环境和停止条件。** 使用同一台 Mac、同一 CPython 与配置；记录机器、系统、解释器版本和路径、GC、计时器、开始结束时间。校准和正式会话均逐输入在首批之前及末批之后检查 AC Power 与 lowpowermode = 0，保存带时间的原始系统读数；会话中防止睡眠，避免其他测试、构建和高负载任务。任何输出错误、输入被修改、异常、电源读取失败或条件不满足，立即保存失败位置和已取得的记录并退出，不自动重试或拼接会话。
- **原始时间记录。** 每批保留输入 ID、输入摘要、n、方法、阶段、轮号、实际顺位、B、起止读数、elapsed_ns 和逐次输出校验凭据。校准时另存三批中位数、阈值及选定 B。保留全部正式批次，不按速度筛选、剔除异常值或更换输入。

## 4. 键比较计数

计数测量独立于计时。每个输入每种方法运行一次，使用相同的排序入口和配置。将各原始整数分别包装为不可变的值对象，保留原顺序和数值语义，每次排序单独清零计数器；构造包装对象后开始计数，返回或抛错时结束。先保存计数，再解包并按第 1 节校验输出。

- 分别记录包装对象成功处理的 `__lt__`、`__le__`、`__gt__`、`__ge__` 调用数，总数 C 为四项之和。同一次成功比较只记一次；反射分派按实际执行的包装器方法归类，返回 `NotImplemented` 的探测不记数。对相同对象或主元自身实际执行的排序关系同样计数。
- `==`、`!=` 按底层值判等，哈希等于底层整数哈希，使集合、字典和算法内的相等性判断保留原语义。相等性、哈希、对象身份检查、索引及内部结构比较均不计入 C。计数描述排序过程中实际执行的输入键序关系，不代表全部操作或 CPU 指令。
- 输入键与数值哨兵（如正负无穷大）若实际执行上述排序关系，按一次键比较计入对应项，并另记哨兵子计数供核对，不重复加总。冻结的 Jordan 核心也用专用哨兵对象及 `is` 分支；仅通过身份分支处理边界时计零，不人为插入比较。保持原运算语义，遇到不支持的类型按正常 Python 分派处理。
- 原始记录保留输入 ID、方法、n、四项、总数 C、哨兵子计数及解包后输出的校验凭据。计数运行的耗时不用于时间图或速度比。

\chapter{Experimental Method}
\label{chap:methodology}

\section{Study Design}
\label{sec:method-positioning}
\label{sec:method-experiment-stages}
\label{sec:method-scope}

The main experiment compares ordinary lists with an uninstrumented finger
tree on \UnifiedN{} unique inputs from five sources. The input registry,
exclusions, reporting rules and preparation stages were fixed before formal
sampling. Both implementations use the same public Jordan sorting core.
Equivalence checks, qualification and separate batch calibration precede
measurement. The results use one complete session; the earlier failed
attempt and the decision to restart are disclosed below.

\section{Inputs and Qualification}
\label{sec:method-qualification}

The unified registry assigns every input to a source and deduplicates its
rank permutation in the fixed source order. It contains no duplicates.
\UnifiedExcluded{} previously saved seeded inputs of length 1500 were excluded
before this experiment under the resource-scope rule. No input was added or
removed in response to the formal ratios.

\textbf{Common} contains \UnifiedCommonN{} inputs at lengths 32/33, 64/65,
128/129, 256/257 and 512/513. At each length, fixed quotas select increasing
strict-flat sequences, low- and medium-nesting block constructions, and
sequences with a heavily nested suffix. Original and mirrored sequences
remain related constructions.

\textbf{Targeted} contains \UnifiedTargetedN{} inputs at $n=128,129$, using
\texttt{values\_for} with smaller-side parameters $k=3,7,19$ in both directions.
The parameters were chosen to exercise interior splits, not from timing results.

\label{sec:method-structural-extension}
\textbf{Structural} contains \UnifiedStructuralN{} saved inputs: balanced,
skew and repeated shapes at $128,129,256,257,512,513$. Balanced and skew share
the targeted construction; repeated uses a separate template that splits
previous outputs again. Even lengths use the original direction and odd
lengths the mirror, coupling parity with direction.

\textbf{Geometric} contains \UnifiedGeometricN{} inputs obtained by widening
random grid trees into simple orthogonal polygons and recording the boundary
order of intersections with a horizontal line. The grid height is fixed, and
each polygon uses one sampled traversal start and direction. Only the even
lengths $32,64,128,256,512$ occur.

\textbf{Seeded} contains \UnifiedSeededN{} inputs generated by successive
insertions into gaps allowed by the noncrossing condition, with fixed seeds,
gap preferences and direction changes. Its measured lengths are
$32,33,64,70,128,512,513$. Shared random-number streams and related settings
do not constitute independent repetitions.

Before timing, the instrumented and uninstrumented trees were compared on
all registered inputs. Qualification then checked both the ordinary list and
the uninstrumented tree. Two checked instances advanced through the same
prefixes; a fresh checked replay and a fresh minimal call supplied additional
checks. Expected sorted outputs were computed outside the core. This is finite
execution evidence, not a proof of equivalence on all valid inputs.

\section{Compared Configurations and Timing Scope}
\label{sec:method-implementations}

\paragraph{Configuration choice.}
An earlier formal experiment used the instrumented tree with detailed counting
disabled. On its \OldCommonN{} common inputs, the tree was slower throughout,
with median tree/list ratio \OldCommonMedian{}. A separate
\OldDiagnosticN{}-input diagnostic reduced tree medians by
\OldDiagnosticDropLow{}--\OldDiagnosticDropHigh{}\% when field-access
instrumentation was removed. This observation motivated a configuration that
excludes observation machinery from the final timing comparison. It does not
assign an additive share of total algorithm cost to instrumentation, nor
extend the diagnostic result beyond its selected inputs. The earlier
instrumented campaigns and diagnostic retain their original archives, indexed
in \cref{sec:appendix-current-formal,sec:appendix-external-review}.

The uninstrumented tree is generated from the same implementation source by
removing observation statements and wrappers and replacing tracked field
access with ordinary field access. Algorithmic checks and data-structure
operations remain. Preparation and compilation occur once before timing.
Each new tree instance binds the generated methods during its constructor,
inside the timed sorting call. The instrumented tree remains available for
operation counts and validation, outside the formal timing samples.

A subsequent constructor-only microbenchmark on the same machine used fixed
parameters: five warm-up pairs and fifty measured pairs, with 256 retained
instances per batch and alternating configuration order. Its median times
were \UnifiedCtorInstrumented{}~$\mu$s per instance for the instrumented tree
and \UnifiedCtorUninstrumented{}~$\mu$s for the uninstrumented tree. The median
paired difference was \UnifiedCtorDifference{}~$\mu$s. These measure constructor
paths, including automatic GC and loop/storage overhead, not pure method
binding. Objects were released after timing. Nothing was subtracted from the
formal sorting observations.

\section{Timing, Calibration and Scheduling}
\label{sec:method-timing}

Timing uses \nolinkurl{time.perf_counter_ns()}. Each call includes fresh
initialization, the main loop and output recovery; the batch loop and output
append are also inside the interval. Expected-output comparison, explicit
pre-batch garbage collection, compression and persistence are outside it.
Automatic GC remains enabled.

Separate calibration tries common batch sizes
$B=1,2,4,8,16,32,64,128$ in order, using three batches per backend at each
attempted value. It selects the first B for which both calibration medians
reach 10~ms, without consulting the ratio. Each input's B is then held fixed.
Qualification allows 180 seconds per input and 1800 per source; calibration
allows 600 seconds per source. Formal limits are 120 seconds per input and
1800 per source. Preparation completed for every source before sampling.

\subsection{Scheduling and Environment}
\label{sec:method-scheduling}
\label{sec:method-environment}

One continuous session executes common, targeted, structural, geometric and
seeded in that order. Within sources, the protocol shuffles inputs with seed
\texttt{20261015}. Each backend receives \UnifiedWarmups{} warm-ups and
\UnifiedRounds{} measured batches per input. First position alternates by
input index and round, giving each backend ten first positions. No tests,
compilation or other experiments run between sources. Outlier deletion and
speed-based replacement are prohibited.

The environment is Apple M4/arm64 with ten logical CPUs, 16~GiB RAM,
macOS 27.2 and CPython 3.12.14, with optimization disabled. GC thresholds
are 700/10/10. Calibration and formal sampling require AC power and low-power
mode off, checked before and after each input. Sleep is inhibited during the
session. These are discrete power observations, not continuous monitoring.
A preceding ten-input cross-host stability diagnostic informed the choice of
host; it was separate from this experiment and did not change its protocol.

Alternating order balances first position within an input, but cannot remove
all thermal or operating-system effects \parencite{mytkowicz2009wrong}.
Repetition alone does not justify statistical inference
\parencite{kalibera2013benchmarking}.

\subsection{First Attempt and Restart}
\label{sec:method-deviation}

The first attempt stopped when a post-input power check recorded battery
power during the geometric source. Common, targeted and structural had
completed; subsequent work stopped and all partial records were retained.
The cause and exact time of the supply change were not determined.

After the failure diagnosis, the author authorized a restart from the
beginning before any performance ratios were calculated. This was an explicit
departure from the protocol's no-retry rule. The second attempt used the same
inputs, batch sizes, source code and scheduling rules and completed all five
sources. The two attempts are not joined or pooled. Archive validation
confirms the recorded technical conditions; it does not erase the procedural
deviation.

A later, post hoc descriptive check compares the ratios of the
\UnifiedStabilityN{} inputs in the first attempt's three complete sources.
All \UnifiedStabilitySame{} retain the same faster backend. The absolute
relative change $100|r_i^{(2)}/r_i^{(1)}-1|$ has median
\UnifiedStabilityMedian{}\% and maximum \UnifiedStabilityMaximum{}\%.
This check is outside the protocol and excluded from the main statistics.
It describes these two sessions, without establishing equivalence or undoing
the first failure.

\section{Aggregation and Structural Descriptions}
\label{sec:method-aggregation}

A batch contributes one duration divided by B. For each input/backend, the
\UnifiedRounds{} values yield a median, R7-interpolated quartiles and IQR.
The input-level comparison is
\[
 r_i=\frac{\operatorname{median}_{b}(t_{i,\mathrm{tree},b}/B_i)}
 {\operatorname{median}_{b}(t_{i,\mathrm{list},b}/B_i)}.
\]
A ratio below one favors the tree. Comparisons use unrounded values. Each
unique input contributes one ratio; neither the batches nor the calls within
them increase the number of independent inputs. Source, nesting-category and
structural-shape summaries remain descriptive, without significance tests or
confidence intervals over dependent constructions.

For each input, $S_i$ is the number of actually performed splits in its
primary checked qualification trace, and $I_i$ counts those with two nonempty
outputs. The smaller side is the minimum of the two output sizes, measured
in sibling-list pair entries. Define $p_i=I_i/S_i$ for $S_i>0$ and record NA
otherwise. The two backends' logical traces agree. Counting one primary trace
per input avoids multiplying events across backends, peer instances or replays.
The parameter $k$ in the targeted, balanced and skew construction is checked
against the actual smaller side; repeated inputs are reported separately.

\section{Records and Independent Validation}
\label{sec:method-evidence}
\label{sec:method-validation}
\label{sec:method-boundaries}

The preparation archive binds equivalence, qualification, calibration,
source identities and environment. Each formal archive retains input and
configuration identities, outputs, per-input power checks, execution order and
individually committed compressed batches. Independent reconstruction checks
the first qualifying B, sample order, correctness and all reported medians,
quartiles and ratios. The second attempt contains \UnifiedBatches{} formal
batches comprising \UnifiedCalls{} checked sorting calls.

The preparation, formal and subsequent descriptive records are stored,
respectively, in these repository directories:

\section{Historical Study: Separate Scope}

\label{sec:method-case-audit}

The earlier rollback-enabled study compared Python sort, the oracle-backed
reference pipeline and the ordinary-list core. Its recovery preparation,
recognition scope, GC-disabled timing, interpreter and scheduling differ
from the present experiment. Its records remain in the historical archive
(\cref{sec:appendix-history}). They are not pooled with the current comparison

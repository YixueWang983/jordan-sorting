# 主机性能差距分解诊断

目的：解释已有 Windows / Mac 全量测试耗时差异（526.867 / 221.485 秒）和排序每调用耗时差异（输入中位比 1.55–1.63）。全部为诊断，`performance_eligible=false`，不修改原稳定性数据、生产算法、系统电源或安全设置。

开始新诊断前固定此脚本和参数。两端原生 CPython 3.12.14，使用同一脚本摘要和相同项目源码。每台机器串行执行：

1. `components`：5 轮预定种子打乱顺序的解释器整数/对象操作、C 排序/哈希、JSON/gzip、计时器、GC、进程/导入、Git 状态、源码哈希、原生硬件/供电采集和 8 KiB 文件写入探针。文件分别为普通写入、文件 fsync 和项目原子写入；只描述各本机 API 成本，不声称掉电持久性等价。
2. 同一次 components 中，原 10 输入面板每后端预热 2 次、固定 B=16、7 轮交替顺序，检查每个输出和输入哈希。该控制实验排除前次按主机自适应 B 不同这一因素，不替换原始结果。
3. `suite-profile`：完整 870 项测试再运行一次，仅在 unittest 每方法开始/结束记录 wall time 和父进程 CPU time；无逐函数追踪器。用来定位慢模块/测试，不把测试总时长当作排序速度。外部单轮上限 1200 秒，超时保留失败，不自动重试。

输出放仓库外新目录，失败记录保留，不覆盖先前尝试。检查实际解释器构建信息、空闲负载、可见电源/CPU策略与安全状态；未知、权限不足和无法确认的有效频率明确记为未知。Windows 用户已确认 BIOS 固定 5.0 GHz；不根据 CIM 标称频率推翻该声明。

分析时区分实测与假说。原排序计时明确排除 GC collect、输出核对、压缩、文件写入和 fsync，因此这些机制不能直接解释排序计时内部的差异。不得在没有同机控制实验时把硬件/架构/编译器/操作系统的综合差异全部归因于 Windows、Defender 或 VBS。

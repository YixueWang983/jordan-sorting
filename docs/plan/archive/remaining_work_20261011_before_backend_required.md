## 阶段二 扩大输入并完成资源资格审计

**依赖：** 阶段一的版本区分已经确定。**交付：** 冻结的输入 JSON、生成配置、结构统计、资格审计与缺额报告。

沿用 9 月开发记录的工程目标：约 380 个本批唯一 rank 输入，规模为 32/33、64/65、128/129、256/257、512/513。每规模目标最多 2 个 strict-flat，low、medium、heavy 各 12 个；这些是覆盖目标，不代表随机代表性或统计充分性。

1. 把 block 构造推广到预定的可变 excursion 长度与间隔，先用小规模 oracle 和有界枚举核对生成规则；与固定种子的 incremental pool 分开记录。
2. 在生成前固定种子范围、每格候选预算和保留顺序。生成后依据实际结构分类、按 rank 去重，并保留镜像的 base identity。数值重标记不能用来补独立输入数量。
3. 冻结候选表后，再执行 oracle 认证、完整 checked diagnostics 和独立新状态的 minimal 输出比较。记录每个候选的 PASS、DUPLICATE、错误、资源失败和未执行原因。基础输入、镜像派生和每格缺额分别计数；十个长度主要提供五档规模及奇偶覆盖，不能当作十档渐近规模。
4. 重点补齐 256/257 以及 512/513 heavy 的资源资格。1024/1025 单列为可选扩展，不进入当前主表的必需规模。
5. 先明确单例和整批资源预算。现有预检入口记录的是单例 120 秒；9 月方案提出下一轮可采用 180 秒。新预算必须写进新配置，不追改历史运行。

先探测 256/257、512/513 的关键结构，再铺开配额。380 例乘 180 秒对应 19 小时的单轮预算容量，不是耗时预测；候选缺额、诊断和重验另计。性能结果仅描述在固定验证程序与资源预算下通过的输入集合；事前冻结规则仍不能消除资格筛选偏差。

**验收：** 输入、结构分类、来源、重复关系与审计一一对应；所有进入计时主表的输入通过资格审计。若配额不足，先报告缺额和原因并修订实验设计，再冻结最终主表，不能看过耗时后换种子或悄悄删除失败输入。checked 超时既不是输出错误，也不是验证通过。

**论文同步：** Experimental Method 增加生成规则、实际结构分组、去重、镜像与资源预算；Limitations 更新样本范围和缺额。非计时验证单独报告，不改写旧正式实验的 60 个输入。

## 阶段四 实现并验证 finger tree 后端

**依赖：** 主线优先完成阶段三交付；原文核实和独立操作实现可提前穿插开展，正式计时时不并行运行重负载开发任务。**交付：** 可独立测试并接入排序核心的真实后端。是否纳入 10-25 审阅稿，执行 10-16 的进展检查与最迟 10-18 的接入验证门槛；未完成部分继续作为后续任务。

1. 补齐规格中尚未核实的 split 分析来源、镜像 ribs、旋转与重平衡规则，核对 1988 年论文的勘误。为每个操作记录来源、语义、拟采用的实现和成本缺口。
2. 实现真实节点、稳定 handles、两端 fingers、make-list、边界 insert 和 split。先用普通有序列表作为数学模型，对小规模操作序列逐步比较；不以空接口、整树重建或另一种随机树代替目标结构。
3. 接入 list header ownership 与 owner adapter。消除 split 后对全部 pair 逐项改写归属的必要性；检查所有 owner 查询，不能把全扫描转移到查询路径。
4. 核对 partial sorted order 的局部访问、初始化、registry 和最终输出成本。性能账本包含比较、节点访问、旋转、元数据写入和分配，避免只测树 split。
5. 将新后端接入同一 Step 1/2/3 流程；保留几何端点和两种 z1 修正规则。两个后端分别对外部排序判据验证，再做后端间差分。

**验收：** 操作序列、端点、ownership、镜像、错误传播及小规模有效排列检查通过；冻结输入上的输出和完整状态检查通过。same-core replay 仍称状态一致性验证，不称另一套独立算法。正确性、操作界和完整排序复杂度分开陈述。

若无法完成某个理论操作或成本论证，记录具体缺口并优先完成可验证实现；论文按实际达到的层级收束，不能把“接入树后端”写成“实现了线性时间”。

**论文同步：** Background 补充真正使用的原文与勘误；Algorithm 和 Implementation 描述实际实现；更新贡献与限制。尚未完成的部分继续标为计划或限制。

## 两类改动分别说明

**不改变判据的计算重构：**

1. 树 `validated_snapshots()` 在一次调用里执行一次 `_audit(True)`，用其局部
   groups/membership生成不可变逻辑视图，并物化物理视图。`audit_snapshot()`
   原本不再次审计，不能算作消除了一次审计。没有跨调用缓存、更新计数器缓存
   或“验证过”标志。下次验证重新遍历；直接字段破坏仍须拒绝。
2. 从当前完整点顺序建立双向邻接数组，逆序移除 n..4，得到每轮插入后的两邻居、
   插入前前一点的左右邻居及z1跳过标志。旧Step 1/2/3(c)判据使用这些事实，
   仍检查全部历史轮次。不是仅检查新增trace，也不信任旧stage提供预期邻居。
   每次验证重新构建数组；旧stage/trace被篡改后不会沿用旧结果。

邻接事实构造为O(k)访问/空间；旧双侧边界和输出邻接的过滤访问为
3k(k−3)次/长度k验证。这里只计算这三处过滤，初始化trace的过滤等其他工作
另计。`reference_index_calls`是`.index()`调用数，**不是搜索元素访问数**。
完整验证还包含后端检查和普通列表的成员/祖先访问，不能据此声称整个验证器
已无条件达到某个复杂度界。

公共 `validate_paper_jordan_state()` 仍保留每次调用fresh checked replay，
只是采用上述计算重构。`validate_paper_jordan_state_reference()`保留旧过滤算法、
旧重复审计和每前缀fresh replay，用于有界对照。它们共用未改变的阶段语义检查，
所以这是重构对照，不是第二套独立Jordan算法证明。

**改变覆盖安排的新版资格：** `synchronous_checked_prefixes_v2`

| 事项 | v1 | v2 |
| --- | --- | --- |
| 主运行策略 | checked | checked |
| 每个完成前缀的当前状态、完整历史检查 | 有 | 主/同伴分别检查，全部历史仍核对 |
| 每个前缀比较 | 与新建fresh实例比较 | 与独立初始化后同步推进的同伴比较 |
| 最后fresh replay | 最后一次前缀replay | 额外第三实例，保持checked并完整检查后比较 |
| 实例重建/早期轮次重复覆盖 | 每前缀重新构造并从头运行 | 显著减少；不宣称保留了原样覆盖 |
| 错误、pending、结果恢复 | 必须拒绝 | 同一核心检查；失败不返回排序输出 |

两个实例用同类型、同配置、同checked策略，无普通后端回退。每前缀检查对象、
可变registry和节点/handle/header不共享；比较后端身份、初始化列表、点顺序、
pair映射、必要stage结果、backend_work、trace、操作计数和逻辑/物理视图。
`invariant_checks`不作为确定性replay的算法计数；主运行仍每前缀增加一次，
与旧主实例一致。另报同伴检查、最后fresh replay和实际初始化次数。
最后再次审计主状态，避免观察回调修改后却使用上一次成功快照。

唯一Step 1/2/3循环改成内部可暂停迭代器，原runner消费同一迭代器并保持callback
接口，v2同步消费两个迭代器。未另写树专用主循环。**这个入口改动也涉及minimal**：
每轮增加迭代器yield/resume开销，旧pilot不能自动代表新版本性能，需重新绑定源码。
树的插入、split/adopt和局部平衡代码没有修改。

- 每例180秒共享worker预算，整批1200秒；先全部小规模对照，再资源复核。
  不提高旧超时上限。首个错误/超时即停止，已完成版本记录独立gzip原子提交，
  当前backend/mode/最近完成prefix单独持久化。后续NOT_RUN，拒绝覆盖旧归档。
- 观测tree `_audit`次数、实际初始化次数、历史邻接链接/删除次数、旧过滤访问
  与index调用。逐前缀指纹与文件保存开销包含在资源观察中。没有warmup或正式计时。

flat、n≥3、t=n−2时，reference树审计次数仍为`t(t+1)/2+4t`。
v2三次checked运行各t次更新审计，两个同步状态各t次局部审计，最后主/新状态
各一次审计，共`5t+2`。这只针对该固定成功路径的 `_audit` 调用，不是所有输入的
耗时预测，也不能将普通列表没有此同名函数解释成“普通列表没有验证”。

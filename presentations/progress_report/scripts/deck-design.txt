Communication job
By the end, the research-seminar audience should understand that the main gap
between the earlier structural framework and an executable Jordan-sorting
algorithm has been closed at the ordinary-list level, supported by bounded
correctness evidence and a formal experiment under explicit timing scopes.

Audience
Supervisor, examiners, and computer-science research-seminar participants.

Purpose
Report one technical research period, solicit feedback on the possible backend
extension and its evaluation scope, and avoid presenting the thesis as already
submitted.

Narrative
Static structural framework -> executable ordinary-list reconstruction ->
validation and initial controlled experiment -> ordinary-list baseline ->
possible finger-tree backend extension.

Visual system
16:9, white/light-gray canvas, dark navy #102A43, teal #2A9D8F, coral
#E76F51, slate #52606D. Aptos-like Office typography. 36 pt slide titles,
18-22 pt body text, sparse flat layouts, one main claim per slide.

Deck structure
16 main slides plus 5 backup slides, 21 slides in total. Slides 17–21 are
backup slides. Speaker notes contain the talk track and source blocks.
Main presentation targets about 18 minutes.

Final main slide discussion
1. Historical heterogeneous finger tree specifically, or an equivalent
   efficient backend supporting the required list operations?
2. Is a tested, semantically equivalent prototype with experimental comparison
   sufficient, or should the thesis also include an amortized operation-bound
   argument?

Backup slide design
Backup A — Median runtime by size
Show all three algorithms under the recorded call scopes; absolute times
belong to the recorded environment.

Backup B — Paper output provenance
Contrast oracle-derived reference output with paper output recovered from
maintained state; certification and comparison remain outside the paper call.

Backup C — Validation summary
Summarize bounded validation for the current implementation baseline, without
presenting finite checks as a universal correctness proof.

Backup D — Reflected local choices
Show the increasing/decreasing Step 3 choices; Step 1 always selects the
predecessor boundary and Step 2 the successor boundary.

Backup E — Proposed finger-tree backend boundary
Keep paper-facing Step 1/2/3 above a small sibling-list backend interface.
Show the ordinary-list backend as the current validated baseline and the
finger-tree backend as a proposed extension. The semantic operations include
singleton-list creation, insertion at the left or right boundary, splitting
at the new-point value, first/last-child access, ownership preservation, and
stable handles. Efficient tree splitting alone is insufficient if ownership
transfer still scans and rebinds every item. Semantic equivalence is the first
target; any complexity claim requires a separate operation-bound argument.

Evidence boundary
Existing results belong only to the ordinary-list baseline. The current
formal experiment does not validate future finger-tree code; recognition
remains outside it. No linear-time claim is made for the ordinary-list
implementation. A thesis-facing finger-tree backend would require separate
validation and experimental evidence.

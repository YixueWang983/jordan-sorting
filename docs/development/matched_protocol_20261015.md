# 共同输入资格与匹配计时规则 v1（2026-10-15）

后续状态：v1资格尝试发生资源超时，归档原样保留。
[v2验证安排](qualification_validation_v2_20261015.md)已完成20例有界开发复核，
尚未重建完整共同资格。下文输入选择与计时规则不变；“每前缀fresh replay”
仍描述v1，不将v2同步实例安排伪装成同一覆盖契约。

本规则在本轮实际资格执行前提交。机器配置由
`experiments/common_input_protocol.py` 的 `qualification_plan()` 与
`measurement_protocol()` 给出，并保存于验证目录的 `preselected_rules.json`。
规则冻结不等于正式实验获准；本轮执行器只有资格验证，没有计时入口。

## 输入与选择

长度 32/33、64/65、128/129、256/257、512/513。每格 strict-flat 最多2例，
low/medium/heavy 各4例，目标140个不同秩排列；380扩展暂不启动。

- strict-flat 为递增序列及其值域镜像。
- low/medium 使用既有 `block_sequence` 的6/8点块构造、固定种子
  `20261015 + 100*n + candidate_index`。构造名称不是测量类别。
- heavy 为偶数长度递增前缀接嵌套后缀。前缀长度为
  `min(2*candidate_index, 2*floor((n-8)/2))`；后缀值整体平移。
  seed 字段是统一候选标识，heavy/flat 不调用随机数。
- 每个非flat格最多16个base候选及各自镜像；按index递增，先base后mirror。
  先测 oracle 合法性和 `stats.structure_profile`，再按全局秩哈希去重。
  只保留首批达到目标的候选，未满则保留缺口；不按后端结果改变选择。
- 分类沿用零嵌套为flat；否则 depth≤1 且 parented ratio≤0.35 为low；
  否则 depth≤3 且ratio≤0.70 为medium；其余为heavy。
- 记录全部已尝试候选，包括非法、错类、重复；格满后的候选不再生成。
  全部候选规格在生成前写入。每例保存完整秩排列、哈希、原例身份及镜像标志。

这些是固定构造覆盖，非均匀随机抽样。mirror不是独立样本；不同seed的块构造、
不同前缀的nested构造也不能自动视为总体独立抽样。分类是最终几何描述，
不是每个前缀的动态复杂程度保证。

## 最终共同资格的执行范围

沿用当前生产源码，无优化变更。普通列表和树分别通过公开 diagnostics
（checked；每个完成前缀结构检查与同类型、同配置新实例replay）以及另一新状态的
公开 minimal 排序，与外部 `sorted(original)` 各自比较。树在两条路径均显式
`detailed_work=False`。记录processed_count、后端完整身份、输出、trace、metrics。
这轮不增加独立几何解码器逐前缀运行；此前refinement证据独立保留。

资格按长度降序、类别顺序、候选顺序运行，每例轮换首个后端。每例最多180秒，
生成阶段最多180秒，campaign共享1800秒墙钟资源预算；子进程获批剩余时间与
180秒中的较小值。文件落盘和父进程收尾会产生少量额外开销，这不是机器强制的
绝对总耗时上限。每个完成检查独立gzip、fsync后原子提交，父进程超时后恢复。

任一合法输入错误、worker错误或资源超时均停止后续例；原例保留，后续逐例
NOT_RUN。不重试、不换seed、不只发布通过交集。资源墙钟时间包括进程启动、
检查/replay和保存，不能画成排序性能。source/config改变须重建受影响资格；
验证工具需要生产证据的源码版本。旧16例、694例、8例pilot都不自动继承资格。

## 计时规则已固定，执行许可仍待满足

冻结树配置为 `detailed_work=False`，两后端均 `minimal`。每次公开调用重新初始化，
计时包含初始化、全部主循环、输出恢复、批量循环与输出append；oracle、结果比较、
`gc.collect()`、压缩与落盘在时钟外。GC保持开启并记录阈值，不删除局部安全检查。

资格全部通过后，另开 calibration 身份。对每个输入依次尝试
B=1/2/4/8/16/32/64/128，每档各后端3批，交替先后；选第一个使**两个后端**
批次中位数都≥10ms的共同B。不能为两个后端分别选B，也不能以比值最小为依据。
若128仍不够，停止并在正式测量前修订协议。calibration预算600秒，结果不入性能表。
10ms是控制计时粒度的工程规则，不是精度或统计功效保证。

全部B确认并冻结后才允许正式sample。用种子20261015打乱输入顺序，每例先做
每后端5次warmup，再20轮配对batch；以“打乱后的case index + round”交替先后，
20轮中双方各有10次先运行。整个正式campaign1800秒，每例120秒资源预算；
超时失败保留，不靠删例或只汇报已完成部分认定整个实验成功。

统计单位为batch。batch elapsed/B是折算单次耗时，并非B份独立测量。
每输入/后端报告20个batch折算值的中位数与IQR（R7线性插值25%/75%分位），
比较树中位数/列表中位数。20轮是固定资源配置，不是充分样本量证明。
保留慢值和极端值，不做事后裁剪；跨输入分层结果只作描述，不把镜像当独立样本做推断。
pilot的3.02–3.19范围继续限定为其24个组的比值范围，不是置信区间。

正式runner/validator尚需实现并验收此规则，不能把旧pilot参数直接改名为正式实验。
冻结准确源码提交和代码哈希、输入/config哈希、Python路径/版本/flags、
OS/架构/CPU/核数/内存/供电、GC及单调时钟信息。计时在空闲机器单独运行，
不与checked资格或开发负载争用；环境变化记录为事件，不能用重测筛选更好结果。

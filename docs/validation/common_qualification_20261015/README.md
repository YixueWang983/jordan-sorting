## 一次有界热点检查

超时后执行 `profile_qualification.py`：固定64点递增输入，两个后端各做一次
checked和一次minimal，整个worker上限60秒。4次调用均结束并通过外部输出检查，
详细profile和规则在 `profile/`，脚本自身哈希及冻结源码哈希均记录。
这些是故障定位调用，不是替代资格、warmup或性能样本。

树checked的cProfile调用记录显示：62次 `validate_paper_jordan_state`、62次
`_validate_state_against_deterministic_replay`、2,201次 `_audit`。
树minimal没有 `_audit` 或replay。源码说明：每个前缀的公共完整状态验证都重放
到该前缀；重放保持checked策略，其树操作还执行完整后端审计。
这提供了重复审计成本的具体证据，不是“树一定死循环”或“minimal也需要180秒”的证据。

profile的累计时间相互包含，不能相加；profiler本身会改变耗时。没有将这些时间
作为配对性能结果，没有外推513点的完成时间，也没有据此归因原pilot的3.02–3.19比值。
没有修改生产代码或减少检查来让本轮通过。
